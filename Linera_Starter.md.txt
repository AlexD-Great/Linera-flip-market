## 🏗️ Architecture Overview

### **Three-Layer Architecture**

1. **Contract Layer** (`contract.rs`)
   - Handles state mutations
   - Processes operations (CreateFlip, PlaceBet)
   - Manages cross-chain messages
   - Persists state using Views

2. **Service Layer** (`service.rs`)
   - Exposes GraphQL API
   - Handles read-only queries
   - No state mutations
   - Serves data to frontend

3. **State Layer** (`state.rs`)
   - Defines data structures
   - Uses Linera Views for persistence
   - Manages MapView, RegisterView, etc.

---

## 🔑 Key Concepts

### **Linera Views**

Views are Linera's way of managing persistent state. They map complex data structures onto a key-value store.

**Available View Types**:
- `RegisterView<T>` - Single value storage
- `MapView<K, V>` - Key-value map
- `CollectionView<K, V>` - Collection of values
- `LogView<T>` - Append-only log
- `QueueView<T>` - FIFO queue
- `SetView<T>` - Set of unique values

**Example**:
```rust
#[derive(RootView)]
#[view(context = ViewStorageContext)]
pub struct FlipMarketState {
    pub flips: MapView<u64, Flip>,           // Map of flip_id -> Flip
    pub next_flip_id: RegisterView<u64>,     // Counter
    pub leaderboard: MapView<String, u64>,   // player -> wins
}
```

### **Microchains**

Each user/application can have its own microchain:
- **Fast**: ~200ms block finality
- **Scalable**: Parallel execution
- **Secure**: Cross-chain messaging
- **Efficient**: Only pay for what you use

## 📦 Core Components

### 1. **ABI Definition** (`lib.rs`)

Defines the interface between contract and service.

```rust
pub struct FlipMarketAbi;

impl ContractAbi for FlipMarketAbi {
    type Operation = Operation;      // User operations
    type Response = ();              // Operation responses
}

impl ServiceAbi for FlipMarketAbi {
    type Query = Request;            // GraphQL queries
    type QueryResponse = Response;   // GraphQL responses
}

#[derive(Debug, Deserialize, Serialize)]
pub enum Operation {
    CreateFlip { bet_amount: Amount },
    PlaceBet { flip_id: u64, prediction: CoinSide },
}
```

**Key Points**:
- `Operation` defines what users can do
- `ContractAbi` for state mutations
- `ServiceAbi` for read-only queries
- Keep operations simple and focused

### 2. **State Management** (`state.rs`)

Define your state using Views for automatic persistence.

```rust
use linera_sdk::views::{MapView, RegisterView, RootView, ViewStorageContext};

#[derive(RootView)]
#[view(context = ViewStorageContext)]
pub struct FlipMarketState {
    pub flips: MapView<u64, Flip>,
    pub next_flip_id: RegisterView<u64>,
    pub leaderboard: MapView<String, u64>,
}

#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct Flip {
    pub id: u64,
    pub creator: String,
    pub bet_amount: Amount,
    pub player1: Option<(String, CoinSide)>,
    pub player2: Option<(String, CoinSide)>,
    pub result: Option<CoinSide>,
    pub winner: Option<String>,
}
```

**Best Practices**:
- ✅ Use `#[derive(RootView)]` for main state
- ✅ Use appropriate View types for data
- ✅ Keep nested structs serializable
- ✅ Use `Option<T>` for nullable fields
- ❌ Don't use `HashMap` directly (use `MapView`)
- ❌ Don't use `Vec` for large collections (use `CollectionView`)

### 3. **Contract Logic** (`contract.rs`)

Implements the core business logic.

```rust
use linera_sdk::{Contract, ContractRuntime, views::{RootView, View}};

pub struct FlipMarketContract {
    state: FlipMarketState,
    runtime: ContractRuntime<Self>,
}

impl Contract for FlipMarketContract {
    type Message = ();
    type InstantiationArgument = ();
    type Parameters = ();
    type EventValue = ();

    async fn load(runtime: ContractRuntime<Self>) -> Self {
        let state = FlipMarketState::load(runtime.root_view_storage_context())
            .await
            .expect("Failed to load state");
        FlipMarketContract { state, runtime }
    }

    async fn instantiate(&mut self, _argument: Self::InstantiationArgument) {
        self.runtime.application_parameters();
        self.state.next_flip_id.set(0);
    }

    async fn execute_operation(&mut self, operation: Self::Operation) -> Self::Response {
        match operation {
            Operation::CreateFlip { bet_amount } => {
                let flip_id = *self.state.next_flip_id.get();
                let creator = self.runtime.authenticated_signer()
                    .expect("Missing signer");
                
                let flip = Flip {
                    id: flip_id,
                    creator: creator.to_string(),
                    bet_amount,
                    player1: None,
                    player2: None,
                    result: None,
                    winner: None,
                };
                
                self.state.flips.insert(&flip_id, flip)
                    .expect("Failed to insert flip");
                self.state.next_flip_id.set(flip_id + 1);
            }
            // ... other operations
        }
    }

    async fn execute_message(&mut self, _message: Self::Message) {
        panic!("Messages not supported");
    }

    async fn store(mut self) {
        self.state.save().await.expect("Failed to save state");
    }
}
```

**Key Methods**:
- `load()` - Load state from storage
- `instantiate()` - Initialize new application
- `execute_operation()` - Handle user operations
- `execute_message()` - Handle cross-chain messages
- `store()` - Persist state changes

**Runtime APIs**:
```rust
// Get authenticated user
let signer = self.runtime.authenticated_signer()?;

// Get system time
let time = self.runtime.system_time();

// Get application parameters
let params = self.runtime.application_parameters();

// Get chain ID
let chain_id = self.runtime.chain_id();
```

### 4. **Service Layer** (`service.rs`)

Exposes GraphQL API for queries.

```rust
use linera_sdk::{Service, ServiceRuntime, views::View};
use async_graphql::{Object, Schema, Request, Response};

pub struct FlipMarketService {
    state: FlipMarketState,
    runtime: Arc<ServiceRuntime<Self>>,
}

impl Service for FlipMarketService {
    type Parameters = ();

    async fn new(runtime: ServiceRuntime<Self>) -> Self {
        let state = FlipMarketState::load(runtime.root_view_storage_context())
            .await
            .expect("Failed to load state");
        FlipMarketService {
            state,
            runtime: Arc::new(runtime),
        }
    }

    async fn handle_query(&self, request: Request) -> Response {
        let flips = self.collect_flips().await;
        let leaderboard = self.collect_leaderboard().await;
        
        let schema = Schema::build(
            QueryRoot { flips, leaderboard },
            MutationRoot { runtime: self.runtime.clone() },
            EmptySubscription,
        ).finish();

        schema.execute(request).await
    }
}

// GraphQL Query Root
struct QueryRoot {
    flips: Vec<FlipInfo>,
    leaderboard: Vec<LeaderboardEntry>,
}

#[Object]
impl QueryRoot {
    async fn flips(&self) -> &Vec<FlipInfo> {
        &self.flips
    }

    async fn leaderboard(&self) -> &Vec<LeaderboardEntry> {
        &self.leaderboard
    }
}
```

**Best Practices**:
- ✅ Collect data before building schema (avoid lifetime issues)
- ✅ Use `async_graphql` for GraphQL
- ✅ Keep queries read-only
- ✅ Use `for_each_index_value()` to iterate Views
- ❌ Don't mutate state in service
- ❌ Don't hold references across await points

## 📚 Common Patterns & Recipes

### **Pattern 1: Counter**

```rust
// State
#[derive(RootView)]
pub struct CounterState {
    pub count: RegisterView<u64>,
}

// Operation
pub enum Operation {
    Increment,
}

// Contract
async fn execute_operation(&mut self, operation: Operation) {
    match operation {
        Operation::Increment => {
            let current = *self.state.count.get();
            self.state.count.set(current + 1);
        }
    }
}
```

### **Pattern 2: Ownership Transfer**

```rust
// State
#[derive(RootView)]
pub struct TokenState {
    pub owner: RegisterView<String>,
}

// Operation
pub enum Operation {
    Transfer { new_owner: String },
}

// Contract
async fn execute_operation(&mut self, operation: Operation) {
    match operation {
        Operation::Transfer { new_owner } => {
            let current_owner = self.runtime.authenticated_signer()
                .expect("Missing signer");
            
            if self.state.owner.get().as_str() == current_owner.to_string() {
                self.state.owner.set(new_owner);
            } else {
                panic!("Not authorized");
            }
        }
    }
}
```

### **Pattern 3: Leaderboard**

```rust
// State
#[derive(RootView)]
pub struct GameState {
    pub scores: MapView<String, u64>,
}

// Update score
async fn update_score(&mut self, player: String, points: u64) {
    let current = self.state.scores
        .get(&player)
        .await
        .expect("Failed to read")
        .unwrap_or(0);
    
    self.state.scores
        .insert(&player, current + points)
        .expect("Failed to update");
}

// Query top players
async fn collect_leaderboard(&self) -> Vec<LeaderboardEntry> {
    let mut entries = Vec::new();
    
    self.state.scores
        .for_each_index_value(|player, score| {
            entries.push(LeaderboardEntry {
                player,
                score: *score,
            });
            Ok(())
        })
        .await
        .expect("Failed to iterate");
    
    entries.sort_by(|a, b| b.score.cmp(&a.score));
    entries.truncate(10); // Top 10
    entries
}
```

### **Pattern 4: Time-Based Logic**

```rust
use linera_sdk::base::Timestamp;

// Check if expired
async fn execute_operation(&mut self, operation: Operation) {
    let now = self.runtime.system_time();
    let deadline = Timestamp::from(1234567890);
    
    if now > deadline {
        panic!("Deadline passed");
    }
    
    // Continue with operation...
}
```

### **Pattern 5: Cross-Chain Messaging**

```rust
// Define message type
pub enum Message {
    Transfer { amount: Amount, recipient: String },
}

// Send message
async fn execute_operation(&mut self, operation: Operation) {
    match operation {
        Operation::SendCrossChain { target_chain, amount } => {
            self.runtime.send_message(
                target_chain,
                Message::Transfer {
                    amount,
                    recipient: "...".to_string(),
                },
            );
        }
    }
}

// Receive message
async fn execute_message(&mut self, message: Message) {
    match message {
        Message::Transfer { amount, recipient } => {
            // Handle incoming transfer
        }
    }
}
```

## 🐛 Debugging & Troubleshooting

### **Common Errors**

#### **1. "Failed to load state"**
```rust
// ❌ Wrong
let state: MyState = runtime.key_value_store().read_value(b"state").await?;

// ✅ Correct
let state = MyState::load(runtime.root_view_storage_context()).await?;
```

#### **2. "Lifetime issues in service"**
```rust
// ❌ Wrong - holding references
struct QueryRoot<'a> {
    state: &'a MyState,
}

// ✅ Correct - collect data first
async fn handle_query(&self, request: Request) -> Response {
    let data = self.collect_data().await;
    let schema = Schema::build(QueryRoot { data }, ...).finish();
    schema.execute(request).await
}
```

#### **3. "Type mismatch with CoinSide"**
```rust
// Make sure to import from the same module
// ❌ Wrong
use flip_market::CoinSide;
use state::CoinSide; // Duplicate!

// ✅ Correct
pub mod state;
pub use state::CoinSide; // Re-export from lib.rs
```

#### **4. "MapView returns Cow<T>"**
```rust
// ❌ Wrong
let value = map.get(&key).await?;
entries.push(value); // Type error!

// ✅ Correct
let value = map.get(&key).await?;
entries.push(*value); // Dereference Cow
```

## ✅ Best Practices

### **State Management**
- ✅ Always use Views for state
- ✅ Use `#[derive(RootView)]` on main state
- ✅ Call `state.save()` in `store()` method
- ✅ Use appropriate View types (MapView, RegisterView, etc.)
- ❌ Don't use HashMap/Vec directly
- ❌ Don't forget to save state

### **Contract Logic**
- ✅ Keep operations simple and focused
- ✅ Validate inputs early
- ✅ Use `authenticated_signer()` for auth
- ✅ Handle errors gracefully
- ❌ Don't panic unnecessarily
- ❌ Don't do heavy computation

### **Service Layer**
- ✅ Keep queries read-only
- ✅ Collect data before building schema
- ✅ Use pagination for large datasets
- ✅ Cache expensive queries
- ❌ Don't mutate state
- ❌ Don't hold references across awaits

### **Testing**
- ✅ Write unit tests for logic
- ✅ Test edge cases
- ✅ Test on local network first
- ✅ Test cross-chain scenarios
- ❌ Don't skip testing
- ❌ Don't test only happy paths

### **Security**
- ✅ Validate all inputs
- ✅ Check authentication
- ✅ Use proper access control
- ✅ Handle overflow/underflow
- ❌ Don't trust user input
- ❌ Don't expose sensitive data
